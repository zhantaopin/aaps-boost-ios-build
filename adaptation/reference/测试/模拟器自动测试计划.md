## 测试总目标

**证明 minSdk 27 设备上 AAPS 不会因 API 28+ 类/方法触发启动期崩溃，且加密路径（SecureEncryptImpl）能正常走完整 encrypt→decrypt 流程。**

## 用例清单（共 7 个，按依赖顺序执行）

### TC-01 多 flavor 构建验证（P0，耗时 15-20min）

**目的**：确保 SecureEncryptImpl 修复在所有 flavor 下 BUILD SUCCESSFUL，无 flavor-specific manifest 或依赖差异引入新问题。

```bash
cd /home/kylin/桌面/AAPS/AndroidAPS-official-4.0.0
for f in full aapsclient aapsclient2 aapsclient3 pumpcontrol; do
  echo "=== $f ==="
  ./gradlew :app:assemble${f^}Release --console=plain 2>&1 | tail -5
done
```

**通过标准**：6 个 flavor 全部输出 `BUILD SUCCESSFUL`；无 flavor 报 `Unresolved reference` 或 `NoSuchMethod` 编译错误。

**失败诊断**：如果某 flavor 单独挂，对比 `app/src/<flavorName>/` 下的 manifest / 依赖声明差异。

### TC-02 APK 签名覆盖安装（P0，耗时 30s）

**目的**：把最新 unsigned APK 用 demo keystore 签名，卸载旧包、安装新包，避免残留旧 dex。

```bash
cd /home/kylin/桌面/AAPS/AndroidAPS-official-4.0.0
APK_SRC="app/build/outputs/apk/full/release/app-full-release-unsigned.apk"
APK_DST="/tmp/aaps-signed-$(date +%s).apk"
/home/kylin/Android/Sdk/build-tools/37.0.0/apksigner sign \
  --ks _docs/demo_keystore.jks --ks-pass pass:androidaps --key-pass pass:androidaps \
  --ks-key-alias key0 --out "$APK_DST" "$APK_SRC" \
  && /home/kylin/Android/Sdk/build-tools/37.0.0/apksigner verify "$APK_DST" \
  && /home/kylin/Android/Sdk/platform-tools/adb -e uninstall info.nightscout.androidaps \
  && /home/kylin/Android/Sdk/platform-tools/adb -e install -r -d "$APK_DST"
```

**通过标准**：apksigner exit=0 + verify exit=0；`pm install` 返回 `Success`；`dumpsys package info.nightscout.androidaps` 能读到完整 Activity Resolver Table。

**注意**：用 `$(date +%s)` 每次生成唯一 APK 名，避免覆盖 `/tmp/aaps-fixed-signed.apk` 这个已验证过的版本。

### TC-03 启动存活期测试（P0，耗时 10min）

**目的**：冷启动后观察 10 分钟内是否发生启动期崩溃（NoSuchMethodError / NoClassDefFoundError 是高频崩溃时机）。

```bash
# 清 logcat + 强制停止 + 启动
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -c
/home/kylin/Android/Sdk/platform-tools/adb -e shell am force-stop info.nightscout.androidaps
/home/kylin/Android/Sdk/platform-tools/adb -e shell am start -S -n info.nightscout.androidaps/app.aaps.ComposeMainActivity
PID=$(/home/kylin/Android/Sdk/platform-tools/adb -e shell pidof info.nightscout.androidaps | tr -d '\r')
echo "启动 PID=$PID，观察 600s..."

# 轮询 600s，每分钟检查一次进程是否存活
for i in $(seq 1 10); do
  sleep 60
  CUR=$(/home/kylin/Android/Sdk/platform-tools/adb -e shell pidof info.nightscout.androidaps | tr -d '\r')
  if [ -z "$CUR" ]; then
    echo "💥 在第 ${i}min 进程已死！"
    /home/kylin/Android/Sdk/platform-tools/adb -e logcat -d -b crash -t 50
    exit 1
  fi
  echo "✅ ${i}min 存活，PID=$CUR"
done
echo "🎉 10min 存活测试通过"
```

**通过标准**：10 次轮询全部返回非空 PID；`logcat -d -b crash` 输出 0 行。

**失败诊断**：如果某轮询 PID 为空，立刻 dump crash buffer 和完整 logcat 最后 200 行。

### TC-04 加密路径触发 + 关键字验证（P0，耗时 5min）

**目的**：AAPS 启动后 DI 容器初始化 SecureEncryptImpl → 触发 encrypt() / generateAesKey() 路径。grep 关键日志证明：(a) 加密成功走通；(b) API 27 下没有尝试走 StrongBox 分支。

```bash
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -c
/home/kylin/Android/Sdk/platform-tools/adb -e shell am force-stop info.nightscout.androidaps
/home/kylin/Android/Sdk/platform-tools/adb -e shell am start -n info.nightscout.androidaps/app.aaps.ComposeMainActivity
echo "等待 180s 让 DI 初始化 + Worker 触发加密..."
sleep 180

# 正向命中：加密成功日志
echo "=== 加密成功日志 ==="
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -d | grep -i "ENCRYPT.*encrypt() stored" || echo "(未命中，可能密钥已缓存，继续看其他信号)"

# 反证：致命崩溃
echo "=== 致命崩溃搜索 ==="
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -d | grep -iE "NoSuchMethodError|NoClassDefFoundError|StrongBoxUnavailableException.*FATAL|FATAL.*StrongBox" \
  && echo "❌ 发现致命崩溃" || echo "✅ 无致命崩溃"

# 反证：API 28+ 方法/类相关错误
echo "=== API 28+ 门控失效搜索 ==="
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -d | grep -iE "setIsStrongBoxBacked|android\.security\.keystore\.StrongBoxUnavailableException" \
  && echo "❌ 发现 API 28+ 门控绕过" || echo "✅ 无门控绕过"

# 进程仍活着
PID=$(/home/kylin/Android/Sdk/platform-tools/adb -e shell pidof info.nightscout.androidaps | tr -d '\r')
echo "最终 PID=$PID"
```

**通过标准**：
- "致命崩溃搜索" 和 "门控失效搜索" 都输出 `✅`
- 最终 PID 非空
- "加密成功日志" 至少命中一条（若密钥已缓存，可能需要先清 app data 再触发，见 TC-05）

### TC-05 清数据后强制触发密钥生成（P1，耗时 5min）

**目的**：TC-04 如果因为密钥已存在缓存没触发 StrongBox 分支，`pm clear` 清数据强制从零走 generateAesKey() 路径。

```bash
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -c
/home/kylin/Android/Sdk/platform-tools/adb -e shell pm clear info.nightscout.androidaps
/home/kylin/Android/Sdk/platform-tools/adb -e shell am start -n info.nightscout.androidaps/app.aaps.ComposeMainActivity
echo "清数据后启动，等待 240s..."
sleep 240

/home/kylin/Android/Sdk/platform-tools/adb -e logcat -d | grep -iE "ENCRYPT|StrongBox|StrongBoxUnavail|falling back" | tail -20
/home/kylin/Android/Sdk/platform-tools/adb -e logcat -d | grep -iE "NoSuchMethod|NoClassDef" | tail -10
PID=$(/home/kylin/Android/Sdk/platform-tools/adb -e shell pidof info.nightscout.androidaps | tr -d '\r')
echo "最终 PID=$PID"
```

**通过标准**：grep 结果无 `NoSuchMethod` / `NoClassDef`；PID 非空；可能命中 "StrongBox unavailable, falling back to TEE-backed key" 日志（证明 catch Exception + 字符串类名匹配分支被走到且安全）。

### TC-06 全库三维 API 门控静态复扫（P0，耗时 30s）

**目的**：运行前次 SKILL.md 2.2.1 节的三维 grep，确保没有新引入的 API 28+ 绕过点。

```bash
cd /home/kylin/桌面/AAPS/AndroidAPS-official-4.0.0
echo "=== 维度 1: 方法调用 ==="
grep -rInE "\.setIsStrongBoxBacked|\.setKeyAgreementParam|\.setAttestationChallenge|KeyProtection\.Builder.*setIsStrong" --include="*.kt" --include="*.java" implementation/src/androidMain app/src/main 2>/dev/null | grep -v "/test"
echo "=== 维度 2: catch 子句 API 28+ 异常类 ==="
grep -rInE "catch\s*\([^)]*:?\s*android\.(security\.keystore\.(StrongBoxUnavailableException|KeyStoreException)|app\.(ForegroundServiceStartNotAllowedException)|os\.(NotificationManager\.)?NotificationListenerServiceNotInitializedException)" --include="*.kt" --include="*.java" implementation/src/androidMain app/src/main 2>/dev/null
echo "=== 维度 3: import API 28+ 异常类 ==="
grep -rInE "import android\.security\.keystore\.StrongBoxUnavailableException|import android\.app\.ForegroundServiceStartNotAllowedException" --include="*.kt" --include="*.java" implementation/src/androidMain app/src/main 2>/dev/null
echo "=== 维度 4: Build.VERSION_CODES 正确门控抽查 ==="
grep -rIn "Build.VERSION_CODES" --include="*.kt" implementation/src/androidMain 2>/dev/null | grep -vE "VERSION_CODES\.(P|Q|R|S|TIRAMISU|UPSIDE_DOWN_CAKE)[^a-zA-Z0-9_]|SDK_INT >=|SDK_INT >=" | head -20
echo "(done)"
```

**通过标准**：维度 1-3 零命中；维度 4 只抽查输出，人工复核是否所有 `VERSION_CODES.P` 引用都伴随 `SDK_INT >=` 门控。

  ↓
TC-02 APK 签名覆盖安装        ← 装最新包

  ↓

  ↓ (若加密日志没出来，执行 TC-05)

## 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| Gradle daemon 300s timeout | TC-01 部分 flavor 挂 | `./gradlew --stop` + 不用 `--no-daemon`；daemon 冷启动 2-3min，后续复用快 |
| emulator-5554 中途崩了 | TC-03/04 全部断 | 用户宿主机手动重启 `emulator -avd API27_Phone -no-snapshot-load`；等 `sys.boot_completed=1` 再继续 |
| TC-01 某 flavor manifest 有 API 28+ 权限声明 | 编译过但安装崩 | 看具体 flavor 的 `AndroidManifest.xml`，加 `tools:node="replace"` 或运行时权限门控 |
| apksigner 交互式卡壳 | TC-02 签名挂 | 必须用 `--ks-pass pass:xxx --key-pass pass:xxx` 非交互参数，之前踩过这个坑 |

## 产物与交付

- 每个 TC 的 stdout 输出直接在终端展示，不落文件
- 最终成功判定以 **7/7 通过** 为验收标准（TC-07 可选，6/7 也算通过）
- 失败时 crash 日志 dump 到 `/tmp/aaps-crash-$(date +%s).txt` 方便事后复盘
